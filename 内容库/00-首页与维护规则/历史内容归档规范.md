# 历史内容归档规范

本文件是本项目发布后历史内容归档的唯一格式规范。

## 归档触发条件

仅当用户已明确说明内容实际发布、明确要求确认写入知识库（或确认归档），且可以唯一确定实际采用的标题、正文与发布日期时，才可写入历史库。

## 文件位置与命名

- 目录：`内容库/01-历史内容/YYYY/YYYY-MM/`
- 文件名：`YYYY-MM-DD｜内容标题.md`
- 一条视频只建立一篇笔记；写入前检查同名或疑似重复笔记，禁止覆盖。

## Frontmatter 固定字段

`title`、`status`、`publish_date`、`business_line`、`theme`、`content_type`、`audience`、`pain_scene`、`content_goal`、`region`、`platform`、`series`、`source`。

其中 `business_line`、`theme`、`content_type`、`audience` 优先采用 [[固定选项库]] 的值；`region` 固定为“广州”，`platform` 固定为“微信视频号”。

## 正文固定结构

```markdown
# 内容标题

## 内容概述

用 2—4 句说明讨论的问题、判断边界和适用场景。

## 目标客户

说明客户类型及所处企业阶段。

## 目标客户痛点场景

描述客户在何种业务状态下遇到何种决策困难。

## 内容正文

保留实际发布的完整正文，不补充未发布事实。

## 可延展选题

- 延展选题 1
- 延展选题 2

## 关联内容

- 暂无直接关联内容
```

不保存备用标题、创作过程、风险评估、镜头或版式信息；不编造发布数据、客户反馈、政策结论或案例。

## 归档完成检查

- [ ] 已确认实际发布标题、正文和日期。
- [ ] 路径、文件名和 Frontmatter 字段完整且符合固定选项。
- [ ] 正文结构完整，未写入未发布或无法核验的事实。
- [ ] 已检查重复，并更新内容地图、月度复盘和缺口分析。
