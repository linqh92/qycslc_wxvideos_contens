# 企业财税-老陈｜微信视频号内容生产库

## 项目维护规则

- [GitHub 同步提交规则](GitHub-同步提交规则.md)：用户明确要求同步、提交或 push 到 GitHub 时的唯一执行规则。

本仓库用于管理“企业财税-老陈”微信视频号的内容资产与生产流程：收集灵感、生成选题、撰写文案、确认发布、归档复盘。

内容围绕成熟企业的股权架构、公司治理、股权交易及相关财税合规服务展开，重点服务有股权设计、治理优化、交易安排与合规需求的企业经营者。账号业务定位不因流程调整而改变。

## 三层架构

| 层级 | 职责 | 位置 |
| --- | --- | --- |
| Agent | 判断用户任务、路由 Skill、控制阶段与写入边界 | `AGENTS.md`、`.codex/agents/video-account-operator.toml` |
| Skills | 分别执行灵感录入、选题规划、文案制作、发布归档 | `.codex/skills/` |
| Knowledge Base | 保存账号专属定位、规则、历史内容、选题、复盘与素材 | `内容库/` |

## 从哪里开始

根据当前需求选择一个入口：

- 要保存同行文案、图片文字或自己的想法：录入灵感。
- 要获得可选选题：发起选题需求。
- 已确认一个选题，要撰写视频文案：生成文案。
- 内容已实际发布，要留存正式记录：发布并归档。

## 子流程：灵感录入

灵感录入是独立流程。完成录入后，不会自动进入选题、文案或归档。

```mermaid
flowchart TD
    A["用户提供文字、图片或图文混合素材"] --> B{"素材形式"}

    B -->|文字| C["原样记录用户文字"]
    B -->|图片| D["提取图片中的可读文字"]
    B -->|图文混合| E["分别记录用户文字与图片文字"]

    D --> F{"识别是否完整？"}
    F -->|是| G["标记：文字识别完整"]
    F -->|否| H["标记：文字识别不完整，不补写推断"]

    C --> I["建立单条灵感笔记"]
    E --> I
    G --> I
    H --> I

    I --> J["存入灵感库/年份/月份/"]
    J --> K["状态：待分析"]
    K --> L["流程结束"]
```

### 灵感录入规则

- 一个灵感对应一篇独立笔记，存放在 `内容库/03-选题规划/灵感库/`。
- 同行文案可完整录入标题与正文。
- 图片仅提取可读文字，不保存、嵌入或链接图片。
- 图片文字不完整时，保留已识别内容并标记“文字识别不完整”，不补写推断。
- 用户未要求分析时，只完成录入；后续发起选题或分析时，才会读取相应灵感。

## 子流程：选题生成

每次选题由用户的当次需求触发，统一提供 5 个互不重复的方案。

```mermaid
flowchart TD
    A["用户提出选题需求"] --> B["读取账号定位与服务范围"]
    B --> C["读取已发布历史内容"]
    C --> D["读取内容地图、选题池与可用灵感"]

    D --> E["形成候选方向"]
    E --> F["检查主题、场景、目标客户与表达角度是否重复"]
    F --> G["评估需求关联、服务承接、内容缺口、差异化与事实可核验性"]

    G --> H["筛选 5 个互不重复的选题方案"]
    H --> I["说明标题、目标客户与场景、服务关联、入选理由、核验状态"]
    I --> J["用户选择其一或要求调整"]
```

候选方向主要来自以下内容：

1. 用户本次明确提出的主题或业务需求；
2. 灵感库中可用于分析的单条灵感；
3. 已发布内容可自然延展、但尚未覆盖的经营场景；
4. 各业务方向选题池中的成熟候选；
5. 内容地图识别出的客户痛点与主题缺口。

## 子流程：发布与归档

“确认文案”不等于“已发布”。只有内容实际发布且用户明确要求归档时，才创建正式历史记录。

```mermaid
flowchart TD
    A["用户确认文案"] --> B["状态：已采用"]
    B --> C["用户实际发布内容"]
    C --> D{"是否明确要求归档或写入？"}

    D -->|否| E["不写入历史内容库"]
    D -->|是| F["读取历史内容归档规范"]
    F --> G["核对实际发布标题、正文与发布日期"]
    G --> H["检查与历史内容是否冲突或重复"]
    H --> I["创建历史内容归档笔记"]

    I --> J["更新候选选题状态"]
    J --> K["更新内容地图与重复选题检查"]
    K --> L["沉淀可延展问题、真实反馈为独立灵感"]
    L --> M["归档完成"]
```

历史内容归档格式以 [历史内容归档规范](内容库/00-首页与维护规则/历史内容归档规范.md) 为准；已发布内容库是内容查重与覆盖判断的事实依据。

## 日常使用示例

- “录入这段同行文案到灵感库。”
- “根据当前内容库给我 5 个合伙人退出选题。”
- “选择第 3 个，生成视频号文案。”
- “这条已发布，请按实际标题和正文归档。”

## 内容使用边界

- 内容需服务账号定位，并落到真实企业经营场景。
- 政策、税率、期限、处罚、平台规则与办理流程等确定性信息，需以当前官方来源核验。
- 不虚构政策、案例、数据或处罚结果。
- 不承诺结果，不提供规避监管的表达。
