# 发布与归档模块

## 两个确认节点

1. **文案确认**：用户认可选题或文案后，候选可标记为“已采用”，但不得写入历史内容库。
2. **归档确认**：只有同时满足“用户明确说明实际已发布或更新”和“用户明确要求归档或写入知识库”时，才允许归档。

实际发布信息无法唯一对应标题、正文或日期时，先请用户澄清；不得猜测或覆盖已有记录。

## 归档执行

归档前必须完整读取并遵循 `内容库/00-首页与维护规则/历史内容归档规范.md`。该文件是文件命名、路径、Frontmatter、正文结构和完成检查的唯一规则来源。

归档时：

1. 检查目标目录是否存在同名或疑似重复笔记；有冲突时停止并报告。
2. 仅写入实际采用的标题、正文和实际发布日期；不保存备用标题、创作过程或未发布信息。
3. 将对应选题池条目更新为“已发布”，保留其来源与关联历史内容，防止再次推荐。
4. 更新索引、内容地图、重复检查和内容缺口分析；无新增事实时不强行改写统计。

## 回流灵感库

归档后，从已发布内容中提取 1—2 个不重复的后续问题，为每条后续问题新建一篇“历史延展”灵感笔记；若存在真实评论、咨询或服务交付反馈，也分别新建独立灵感笔记，并关联本次历史内容。

回流条目先标记为“待分析”，不能直接成为下一次正式选题。这样形成：

`发布内容与真实反馈 → 灵感库 → 筛选入池 → 下一次选题`
