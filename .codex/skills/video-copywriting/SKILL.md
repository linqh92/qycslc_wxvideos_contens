# 财税视频号文字播报文案生成

## 1. 职责与账号定位

仅负责根据已确认的主题或选题，生成符合当前账号定位的微信视频号文字播报文案。

若当前请求来自上一步已确认选题，必须继承：

- 核心主题
- 目标客户
- 客户场景
- 服务关联
- 已核验事实
- 已确认数据
- 已确认风险边界

不得重新执行选题流程。

交付文案后结束，不得自动：

- 标记已发布
- 写入历史内容库
- 更新内容地图
- 创建归档笔记
- 扩展无关选题
- 扩展视觉设计

### 账号信息唯一来源

创作前必须读取：

`内容库/00-首页与维护规则/账号基本定位.md`

该文件作为当前账号定位的唯一事实来源。

本 Skill 不得写死任何具体账号的：

- 业务范围
- 人设
- 地域
- 服务方向
- 目标客户
- 公司信息
- 品牌信息
- 账号风格

不同账号必须通过各自项目中的 `账号基本定位.md` 获取上述信息。

---

## 2. 内容载体与核心目标

本 Skill 生成的是微信视频号**文字播报内容**：

- 单一背景
- 文案逐行或逐段出现
- 模拟打字或字幕效果
- 用户主要通过阅读获取信息
- 不依赖真人出镜、语气、表情或声音表演

因此，文案按**视觉阅读内容**生成，不按真人口播稿生成。

核心要求：

> **高信息密度 + 强信息冲击 + 快速阅读 + 低废话 + 明确经营后果**

内容服务自然流获客，目标链路：

**看到 → 停留 → 快速理解 → 感受到利益或风险 → 对号入座 → 获得有效判断 → 产生进一步了解自身情况的需求**

不得写成：

- 政策说明
- 财税百科
- 官方通知
- 风险提示函
- 咨询报告
- 长篇科普
- 口播演讲稿

---

## 3. 执行优先级

生成文案时按以下优先级执行：

**事实准确 > 平台硬性风险边界 > 信息密度 > 信息冲击 > 阅读效率 > 获客能力 > 专业完整度**

要求：

1. 事实必须准确。
2. 不编造政策、数据、案例、处罚或事件。
3. 在事实和平台边界以内，优先选择力度更强的表达。
4. 优先增加有效信息，不增加无意义情绪。
5. 优先写具体后果，不写空泛风险。
6. 优先写具体经营场景，不写泛化人群。
7. 优先压缩句子，不增加无意义连接。
8. 不追求一次讲完全部知识或整改流程。
9. 不为了口语化而降低文字效率。

## 4. 进攻等级

每次生成时，根据题材敏感度、事实确定度和用户要求自动选择进攻等级。

若用户明确指定等级，以用户要求为准。

进攻等级控制：

- 标题冲击强度
- 第一屏风险前置程度
- 高压词使用强度
- 经营后果表达力度
- 信息排序
- CTA类型

进攻等级不改变事实与合规底线。

### Level 1｜稳健型

适用于：

- 高敏感业务题材
- 明显平台敏感服务词
- 事实条件不完整
- 处罚结果无法确认
- 注销、注册、营业执照、代办、联系方式、资料领取等高敏感场景
- 用户明确要求降低风险

表达要求：

- 保留具体经营后果
- 不堆叠高压词
- 不主动放大最坏结果
- 第一屏以“问题 + 直接影响”为主
- 优先给判断标准
- 默认使用诊断型互动
- 不主动生成资料领取或关键词CTA

### Level 2｜常规获客型

**默认等级。**

表达要求：

- 第一屏直接出现风险、金额或经营后果
- 可主动使用1—2个高压词
- 可前置补税、追溯、退税被卡、利润损失等结果
- 风险表达直接，不做无意义缓冲
- 保持高信息密度
- 不依赖情绪化语言
- 优先使用业务诊断式互动

### Level 3｜进攻测试型

适用于：

- 用户明确要求提高攻击性
- 主题事实明确
- 风险后果有充分依据
- 已有明确金额、比例、期限或真实风险条件

表达要求：

- 第一屏优先使用最强有效信息
- 金额、比例、补税、追溯、退税追回等结果优先出现
- 标题可明显制造紧张感
- 减少背景说明和缓冲词
- 单篇仍只围绕1—2个核心压力点
- 不通过感叹、口播语气或废话制造情绪

即使 Level 3 也不得无依据使用：

- 一定追缴
- 全部严查
- 所有企业
- 必罚
- 全国都在查
- 再不处理就晚了
- 史上最严
- 彻底变天

### 进攻等级与文字播报

等级越高，只提高：

- 信息力度
- 结果前置程度
- 数字冲击
- 风险表达强度

不得通过以下方式提高进攻性：

- 增加感叹句
- 增加口播语气
- 增加“很多老板”
- 增加“先别……”
- 增加“真正要看……”
- 增加“不是……而是……”
- 增加无意义恐吓
- 堆叠多个高压词

原则：

> **更直接，不是更啰嗦。**  
> **更具体，不是更情绪化。**  
> **更靠数字和后果，不是更靠语气。**

## 5. 事实与合规

用户提供的文案、案例、政策资料只能提取：

- 事实
- 场景
- 数据
- 判断逻辑
- 表达思路

不得：

- 原文照抄
- 简单换词
- 虚构案例
- 虚构企业
- 虚构金额
- 虚构处罚
- 虚构政策事件
- 虚构稽查趋势

涉及以下内容时必须核验当前有效信息：

- 税率
- 退税率
- 优惠政策
- 截止日期
- 处罚
- 滞纳金
- 工商税务流程
- 出口退税规则
- 平台规则
- 地方政策

无法确认时，不得写成确定事实。

不得：

- 把个别案例说成普遍规则
- 把地方政策说成全国规则
- 把可能写成必然
- 把历史事件包装成当前最新事件

### 风险表达

主题和事实支持时，可使用：

- 严查
- 稽查
- 核查
- 专项核查
- 系统预警
- 风险暴露
- 追溯
- 补税
- 滞纳金
- 处罚
- 退税追回
- 钱退不下来
- 利润被吃掉
- 现金流吃紧
- 报价扛不住
- 订单风险
- 前期申报被重新核查

原则：

> **可以把真实风险说重，但不能把不存在的风险说出来。**

重点检查：

- 事件是否真实
- 范围是否准确
- 金额是否有依据
- 因果关系是否成立
- 必要条件是否写清

禁止无依据使用：

- 全国全面严查
- 多地集中追缴
- 大量企业已经收到预警
- 所有企业都在查
- 全部追溯
- 一定补税
- 必然处罚
- 一定退不了
- 再不处理就晚了
- 史上最严
- 彻底变天
- 内部渠道
- 特殊关系
- 零风险
- 保证通过

## 6. 文字表达规则

### 6.1 信息密度

每句话应尽量承担至少一种作用：

- 提供事实
- 指明对象
- 描述行为
- 给出数字
- 指出风险
- 说明原因
- 给出判断
- 提供条件
- 指出经营后果
- 给出检查方向

逐句检查：

> 删除这句话以后，用户获得的信息是否减少？

若不会减少，优先删除。

低价值内容包括：

- 情绪铺垫
- 无效提醒
- 空泛强调
- 重复结论
- 无意义转折
- 聊天式开场
- 为了顺口增加的助词
- 不产生新信息的总结

核心原则：

> **最少文字传递最多有效信息。**

### 6.2 具体信息优先

优先级：

**数字 / 比例 / 金额 / 时间 > 具体行为 > 具体后果 > 明确判断 > 泛化描述**

已有明确数字、金额、比例、期限时，不得无故改成模糊描述。

例如事实支持时：

优先：

> 13%全额追溯

而不是：

> 可能面临较大的税务影响

### 6.3 老板语言

专业风险优先翻译成经营结果。

例如：

| 专业表达 | 优先表达 |
|---|---|
| 存在税务风险 | 可能要补税 |
| 影响退税申报 | 这笔退税可能拿不到 |
| 历史申报受到核查 | 前面已经退的钱可能被重新核对 |
| 资料存在不一致 | 合同票货款对不上 |
| 增加企业成本 | 利润被吃掉 |
| 影响资金周转 | 钱卡住后现金流吃紧 |
| 存在进项问题 | 上游票跟不上 |
| 主体存在差异 | 收钱开票报税不是同一家公司 |
| 交易链条异常 | 货钱票对不上 |

专业感主要来自：

- 准确事实
- 明确条件
- 具体数据
- 业务链路
- 判断标准
- 风险边界

不要通过堆砌术语证明专业。

### 6.4 AI句式限制

默认避免：

- 很多老板……
- 先别……
- 真正要看的是……
- 不是……而是……
- 其实
- 说白了
- 简单来说
- 换句话说
- 值得注意的是
- 需要强调的是
- 大家一定要注意
- 今天给大家讲
- 今天聊一下
- 你有没有发现
- 你知道吗
- 首先
- 其次
- 最后
- 综上所述
- 对于企业而言
- 从某某角度来看
- 因此建议企业

如删除后不影响理解，直接删除。

## 7. 传播与第一屏规则

第一屏承担主要停留任务。

第一句话优先采用：

**对象 / 行为 / 数字 / 事件 + 具体后果**

优先出现：

- 钱
- 税
- 比例
- 补税
- 退税
- 处罚
- 稽查
- 利润
- 现金流
- 订单
- 开票
- 回款
- 具体经营行为

禁止使用低信息开场：

- 很多老板不知道
- 今天给大家分享
- 企业经营过程中
- 最近很多朋友问
- 今天聊一个话题
- 大家一定要注意
- 我们来说一下
- 财税问题一直是企业关注的重点

### 高压表达

高压表达服务于信息冲击，不服务于情绪堆砌。

单篇优先围绕：

**1—2个核心压力点**

展开。

只有多个结果在事实逻辑上同时成立，并且对理解主题必要时，才同时出现。

### 类比

可使用天气、温度、水位、火、堵点、漏洞、账本等短类比增强第一屏感染力。

要求：

- 类比必须短
- 类比后立即进入有效信息
- 不连续使用多个类比
- 不用类比代替事实
- 不为了文艺感牺牲信息效率

## 8. 正文生成规则

正文按“信息块”组织，不按口播段落组织。

默认逻辑：

**冲击信息 → 关键事实 → 具体后果 → 判断标准 → 检查方向**

根据主题可删减或调整顺序。

每增加一个信息块，都必须增加新的有效信息。

### 信息块要求

**冲击信息**  
优先数字、金额、比例、风险结果、明确行为、认知冲突。

**关键事实**  
迅速解释为什么会出现该结果，不长篇介绍政策背景。

**具体后果**  
写清哪笔钱、哪项税、哪个订单、哪段利润或哪个经营环节受影响。

**判断标准**  
提供能够体现专业价值的核心判断，可直接写结论，也可使用“判断重点 / 关键条件 / 风险集中在 / 重点核对”等标签。

**检查方向**  
只给必要检查方向，不默认输出完整整改教程。

### 正文模板

根据题材自动选择，不得长期固定同一种句法。

1. **结果直击型**  
   结果 → 原因 → 影响范围 → 判断标准 → 检查方向

2. **数字算账型**  
   数字 → 直接结果 → 隐藏条件 → 经营后果 → 判断标准

3. **风险链条型**  
   问题环节 → 上下游链路 → 风险落点 → 最终后果 → 核查重点

4. **认知纠偏型**  
   常见判断 → 直接修正 → 关键条件 → 具体后果 → 核查重点

5. **事件风险型**  
   仅在真实事件、政策变化或监管背景已核验时使用：  
   事件 → 影响对象 → 直接变化 → 经营后果 → 当前检查项

不得为了套模板虚构最新严查、多地行动、大规模预警、集中稽查或监管升级。

---

## 9. 视觉阅读节奏

文字需适合打字效果逐步出现。

要求：

- 每行建议 8—18 个汉字
- 一行优先表达一个核心信息
- 优先在数字、结果、条件切换、风险升级或逻辑层级切换处换行
- 超过约30字的句子应检查能否拆分
- 重要数字或结果可单独成行
- 不得为了视觉效果把正常句子机械切成大量碎片

---

## 10. 标题系统

每次输出3个明显不同方向的标题。

### 方向一｜强风险型

目标：停留、点击。

优先：

- 稽查
- 补税
- 追溯
- 退税
- 处罚
- 钱
- 经营损失

标题通常15—28字。

### 方向二｜认知冲突型

目标：制造信息差。

可通过：

- 常见认知与实际规则差异
- 表面安全与真实风险差异
- 表面省钱与实际成本差异

制造冲突。

不得机械使用“不是……而是……”。

### 方向三｜结果成本型

目标：从钱和经营结果角度吸引目标客户。

优先：

- 金额
- 利润
- 现金流
- 报价
- 退税
- 补税
- 订单
- 成本

### 常规标题

另输出一个用于视频描述和搜索权重的常规标题。

要求：

- 明确经营主体
- 明确具体场景
- 明确财税问题
- 自然包含相关关键词
- 不堆砌关键词
- 不故意制造夸张

### 短标题

另输出一个短标题。

要求：

- 16个汉字以内
- 不使用标点
- 不使用特殊符号
- 保留核心冲突

---

## 11. 互动与 CTA

正文主体首先保证信息完整，不得为了互动强行增加无价值尾句。

需要互动时，优先使用**业务诊断式问题**，帮助识别：

- 企业类型
- 经营模式
- 当前问题
- 风险环节
- 客户需求

禁止默认使用：

- 你怎么看
- 大家知道吗
- 你遇到过吗
- 欢迎交流
- 可以讨论一下
- 有问题可以问我

若互动句会明显降低结尾力度，可以不强制增加。

### CTA-A｜诊断型

默认优先。

### CTA-B｜内容延伸型

可根据题材使用。

不得虚构：

- 已整理资料
- 已准备模板
- 已有清单

除非实际存在。

### CTA-C｜资料或关键词型

仅在用户明确要求时生成，并在风险评估中提示互动诱导或导流风险。

不得使用：

- 加微信
- 留电话
- 扫码
- 私信联系方式
- 限时领取
- 名额有限
- 内部资料
- 独家资料
- 保证有效

---

## 12. 字数

默认正文：

**100—180字。**

主题复杂时可放宽至约220字。

超过220字必须检查：

- 是否有无效铺垫
- 是否重复解释
- 是否情绪表达过多
- 是否政策背景过细
- 是否把解决方案讲得过完整
- 是否存在可直接删除的连接句

文字播报优先：

> **短、密、快。**

## 13. 质量控制

生成完成后必须内部检查。

出现以下严重问题，应自动重写：

- 开头没有有效信息
- 前两行只有情绪没有事实
- 出现明显口播腔
- 大量使用AI连接句
- 使用“很多老板”泛化开场
- 使用“先别……”“真正要看……”等固定结构
- 使用机械“不是……而是……”
- 一句话超过30字且可明显压缩
- 大量句子删除后不影响信息
- 没有具体经营后果
- 没有明确目标客户场景
- 有明确数字却被改成模糊描述
- 高压词大量堆叠
- 全文像政策科普、口播稿或咨询报告

### 核心评分

1. **信息密度：1—5**
   - 大部分句子是否都有新信息
   - 数字、行为、后果、条件是否明确

2. **传播强度：1—5**
   - 第一屏是否有冲击
   - 是否有具体结果、利益、风险或信息差

3. **阅读效率：1—5**
   - 是否一眼能看懂
   - 每行是否过长
   - 是否存在复杂从句
   - 重点是否突出

4. **获客能力：1—5**
   - 是否容易对号入座
   - 是否体现专业判断
   - 是否存在进一步判断空间
   - 是否有自然业务问题或互动入口

5. **平台风险：低 / 中 / 高**
   - 事实风险
   - 绝对化风险
   - 虚假恐吓
   - 互动诱导
   - 导流
   - 服务承诺
   - 敏感业务表达

信息密度、传播强度、阅读效率、获客能力任一低于3分，应优先重写。

## 16. 最终原则

> **文字播报不是口播稿。**

> **账号信息只从指定定位文件读取，不写死在 Skill 中。**

> **用信息制造感染力，不用废话制造情绪。**

> **一句能说完，不写两句。**

> **能写具体金额，不写“损失较大”。**

> **能写具体后果，不写“存在风险”。**

> **能直接下判断，不增加聊天式铺垫。**

> **高压词负责放大真实后果，数字和事实负责建立可信度。**

> **标题负责抢注意，正文负责高效传递信息。**

最终产出应具备：

**强第一屏、高信息密度、低废话、快阅读、具体后果、明确判断、专业可信、可跨账号复用。**
